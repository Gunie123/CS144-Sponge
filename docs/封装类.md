# Sponge C++ Socket API 封装深度解读

## 1. 为什么需要封装？
直接调用 Linux 的 POSIX 网络接口有很多缺点：
1. **弱类型与强制转换**：所有操作都基于底层的 `int` 文件描述符 (FD)；IP 地址需要手动将 `sockaddr_in` 强制类型转换成 `sockaddr`。
2. **易发生资源泄漏**：必须手动调用 `close()`，如果在代码中途触发了 `return`、`throw` 等操作忘记 `close()`，会导致内存和文件描述符泄漏。
3. **缺少内存安全机制**：读取数据时通常要手动传指针和缓冲区长度。
4. **字节序混乱**：手动管理大端序（网络字节序）和小端序（主机字节序）。

这四个类解决了上述痛点，构建了一套现代且内存安全的抽象层。

## 2. Address 类解读：智能的网络地址管理器
*源代码位置：`libsponge/util/address.hh`*

### 作用与封装机制
`Address` 封装了 C-style 中的 `sockaddr`，`sockaddr_storage` 结构以及 DNS 解析过程 (封装了 `getaddrinfo`)。你不再需要手动处理大端/小端字节序转换（如 `htons` ），也不用再做凌乱的结构体转换。所有关于“IP + 端口号”的操作都可以用这个单一的类搞定。

### 核心函数功能及参数
* **构造函数**：
  * `Address(const std::string &hostname, const std::string &service)`: **(常用)** 通过主机名（例如 `"www.google.com"`）和服务名（如 `"http"` 或单纯 `"80"`）进行构造，内置了 DNS 解析逻辑。
  * `Address(const std::string &ip, const uint16_t port)`: **(常用)** 通过 点分十进制字符串（如 `"127.0.0.1"`）和整型端口号构造。
* **访问数据**：
  * `ip()` / `port()`: 以 `std::string` 和 `uint16_t` 形式分别返回解析好的 IP 和端口号。
  * `to_string()`: 返回如 `"127.0.0.1:80"` 这样易读的格式化字符串。
* **底层 C 接口交互逻辑**：
  * `operator const sockaddr *() const`: 用于 C++ 的隐式转换。当底层调用 `bind()` 等 C 语言函数需要 `const sockaddr *` 参数时，`Address` 对象会自动“变身”传递指针。
  * `size()`: 返回底层结构体的数据长度，用于配合传入 `socklen_t`。

## 3. FileDescriptor 类解读：基于 RAII 的资源护城河
*源代码位置：`libsponge/util/file_descriptor.hh`*

### 作用与封装机制
这是整个 I/O 的核心基类。Linux 中只要是 I/O 皆为文件，Socket 也是一个整数型文件描述符 (FD)。
`FileDescriptor` 使用了 **RAII（资源获取即初始化）和引用计数 (`std::shared_ptr`)**。
它的内部有一个 `FDWrapper` 私有类去持有整数 `fd_num`。当没有对象再使用这个封装体（即引用计数降为 0），析构函数就会**自动且强制**调用 OS 的 `close(fd)` 关闭底层文件引用，永久消除资源泄露可能。
*注：为了防止误操作，它被设计成**不可拷贝** (`delete copy constructor`)，但可以移动 (`move`)。*

### 核心函数功能及参数
* **基础读写方法**：
  * `read(const size_t limit)`: 封装 POSIX `read(2)`。指定最多读取 `limit` 个字节，无需自己维护 `char*`，直接返回一把纯净的 `std::string`。自动处理到达文件末尾（EOF）的逻辑。
  * `write(const std::string &str)`: 封装 POSIX `write(2)`。将字符串写入底层的 FD，会自动通过循环阻塞等方式尽全力把数据写完。
* **资源管理控制及状态查询**：
  * `close()`: 手动提前调用底层的关闭。由于有 RAII，大多数情况不需要自己调用。
  * `eof() / closed()`: 分别查询 `read` 阶段是否碰到了文件末端 (EOF)，以及这个 fd 是否已被关闭。
  * `set_blocking(const bool blocking_state)`: 通过 `fcntl` 控制该文件是否开启阻塞 I/O 模式。

## 4. Socket 类解读：通用套接字基类
*源代码位置：`libsponge/util/socket.hh`*

### 作用与封装机制
`Socket` 直接继承自 `FileDescriptor`。由于网络套接字也是一种特俗形式的 File/FD，因此它直接具备 `FileDescriptor` 自动释放和读写能力。在此之上，`Socket` 类封装了 Linux 中专属于网络连接的基础 API。

### 核心函数功能及参数
* **通信阶段控制**：
  * `bind(const Address &address)`: 封装 `bind(2)`。将当前的套接字绑定在给定的本地 `Address` 上（通常服务端调用）。
  * `connect(const Address &address)`: 封装 `connect(2)`。向指定的对端 `Address` 发起网络连接（客户端使用）。
  * `shutdown(const int how)`: 封装 `shutdown(2)`。停止套接字的一部分能力。`how` 通常传入 `SHUT_RD`（不再读），`SHUT_WR`（不再写），或 `SHUT_RDWR`。
* **访问当前属性**：
  * `local_address()`: 封装 `getsockname`，查询本端使用的 IP 与端口，返回安全封装的 `Address`。
  * `peer_address()`: 封装 `getpeername`，查询连接对象（对方）的 IP 与端口，返回 `Address`。
  * `set_reuseaddr()`: 包装 `setsockopt` 开启 `SO_REUSEADDR` 选项。它使得端口在强制结束（重启服务端）后立刻可以重新拿来绑定（用于加速 debug）。

## 5. TCPSocket 类解读：TCP 通信终极形态
*源代码位置：`libsponge/util/socket.hh`*

### 作用与封装机制
`TCPSocket` 继承自 `Socket`，它是针对 TCP 协议 (`AF_INET` 和 `SOCK_STREAM`) 具体特化的版本。在 Lab 0 的 webget 实验中，你就是直接实例化这个类。

### 核心函数功能及参数
* `TCPSocket()`: 无参构造函数。内部会自动去操作系统开辟一个 IPv4、面向流（TCP）的 Socket 类型句柄。
* `listen(const int backlog = 16)`: 封装 `listen(2)`。仅服务端使用。将这个套接字标记为“监听态”用来接听别人的连接。`backlog` 参数代表未交接给应用层的连接队列的最大容纳排队数量（默认16）。
* `accept()`: 封装 `accept(2)`。阻塞等待，直到有一个客户端连了进来，**然后它会返回一个全新的 `TCPSocket`** 专门用于与刚接通的这个客户端一对一通信。这是因为原先的 Socket 还要继续留着 `listen()` 别人。
